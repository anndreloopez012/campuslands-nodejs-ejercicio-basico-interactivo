🧰 Caja de Herramientas ESM

¿Qué Usaremos en ESM y Para Qué Sirve?

En EcmaScript Modules la sintaxis cambia respecto a CommonJS. Estos son los componentes oficiales que utilizaremos:

"type": "module" (package.json)

¿Para qué sirve? Le ordena al motor Node.js que interprete todos los archivos .js del proyecto como módulos modernos de EcmaScript, habilitando import, export y Top-Level await.

import / export vs require / module.exports

¿Para qué sirve? La sintaxis estandarizada de JavaScript. Con export async function agregarCamper(nombre, stack) compartimos herramientas, y con import { agregarCamper } from './campers.js' las consumimos.

import.meta.url & fileURLToPath

¿Para qué sirve? En ESM la variable global __dirname ya no existe por diseño. Usamos import.meta.url y fileURLToPath para calcular con precisión la ruta de la carpeta actual en cualquier sistema operativo.

node:fs/promises & node:path

¿Para qué sirve? Los módulos nativos de Node se importan con sintaxis limpia: import fs from 'node:fs/promises' y import path from 'node:path'.

Top-Level await (Nativo en ESM)

¿Para qué sirve? En ESM ya no necesitas crear una función async function main() para usar await. Puedes llamar a await fs.readFile() directamente en la raíz de tu script.

Regla de Extensión Obligatoria (.js)

¿Para qué sirve? En ESM nativo de Node.js, las importaciones relativas deben incluir siempre la extensión: import './campers.js' (si omites el .js, Node arrojará un error ERR_MODULE_NOT_FOUND).

2 Paso 2: Activar EcmaScript en Node

Configuración de package.json con "type": "module"

La línea mágica que transforma a Node.js de CommonJS al estándar moderno de EcmaScript.

package.json (Configurado para ESM) 
{
  "name": "campuslands-cli-esm",
  "version": "1.0.0",
  "description": "Gestor en Node puro con EcmaScript",
  // ¡LÍNEA OBLIGATORIA PARA ECMA SCRIPT!
  "type": "module",
  "main": "src/index.js",
  "scripts": {
    "start": "node src/index.js",
    "dev": "node --watch src/index.js"
  },
  "keywords": ["campuslands", "nodejs", "esm"],
  "license": "ISC"
}

"type": "module"

¿Para qué sirve? Activa el soporte de EcmaScript Modules. Si intentas usar import sin esta línea, Node lanzará el error: SyntaxError: Cannot use import statement outside a module.

"start": "node src/index.js"

Ejecuta la aplicación con el comando estándar npm start.

"dev": "node --watch src/index.js"

Auto-recarga nativa. Cada vez que guardes cambios en tus módulos ESM, Node reinicia el script al instante sin librerías externas.

3 Paso 3: Captura de Entradas

Cómo Lee Node la Terminal: process.argv

El objeto global process funciona de forma idéntica en ESM: empaqueta cada argumento de la terminal en un Array.

Si un camper ejecuta este comando en su consola: 

$ node src/index.js agregar "Carlos Morales" "Node.js"

¿Qué genera Node internamente?

Un array con exactamente 5 elementos:

  • [0] ➔ "/usr/local/bin/node" (Binario de Node)
  • [1] ➔ "/campuslands-cli-esm/src/index.js" (Ruta del script ejecutado)
  • [2] ➔ "agregar" (Comando a ejecutar)
  • [3] ➔ "Carlos Morales" (Argumento 1: Nombre)
  • [4] ➔ "Node.js" (Argumento 2: Stack)
Técnica Profesional de Desestructuración 
// src/index.js

// ¿Por qué dejamos 2 espacios vacíos [, ,]?
// Para ignorar [0] (node) y [1] (ruta del script)
// y extraer directamente lo que el usuario escribió:
const [, , comando, arg1, arg2] = process.argv;

console.log("Comando ingresado:", comando);
console.log("Argumento 1:", arg1);
console.log("Argumento 2:", arg2);
¿Por qué comillas dobles para nombres con espacios?
Si escribes agregar Carlos Morales Node.js, Node separará "Carlos" como argumento 1 y "Morales" como argumento 2. Las comillas "Carlos Morales" le indican a la consola que es un único string continuo.
4 Paso 4: Módulo de Persistencia (ESM)

Imports y Rutas Seguras en src/campers.js

Haz clic en cada bloque del código para ver qué hace, cómo opera EcmaScript y por qué usamos import.meta.url.

src/campers.js (Líneas 1 a 18)
1 import fs from 'node:fs/promises';
2 import path from 'node:path';
3 import { fileURLToPath } from 'node:url';
4 const __filename = fileURLToPath(import.meta.url);
5 const __dirname = path.dirname(__filename);
6 const RUTA_DATA = path.join(__dirname, '..', 'data', 'campers.json');
7 export async function leerCampers() {
8 try {
9 const contenido = await fs.readFile(RUTA_DATA, 'utf-8');
10 return JSON.parse(contenido);
11 } catch (error) {
12 if (error.code === 'ENOENT') { return []; }
13 throw error;
14 }
15 }
16 export async function guardarCampers(lista) {
17 await fs.writeFile(RUTA_DATA, JSON.stringify(lista, null, 2), 'utf-8');
18 }
Línea 1 • import fs from 'node:fs/promises' Haz clic en cualquier línea 👈
Línea de código completa:
import fs from 'node:fs/promises';

¿Qué hace esta línea en EcmaScript?

Usa la sintaxis oficial import de EcmaScript para traer el sistema de archivos nativo de Node. Al usar /promises, las operaciones de disco (leer y escribir) retornan Promesas nativas que se resuelven con await sin necesidad de callbacks.

Diferencia con CommonJS: En vez de const fs = require('node:fs/promises'), usamos import fs from 'node:fs/promises'.
5 Paso 5: Lógica y Exportaciones (ESM)

Exportaciones y Lógica en src/campers.js

Desglose de cómo exportar funciones con export, validar entradas y autoincrementar IDs.

src/campers.js (Líneas 19 a 39)
19 export async function agregarCamper(nombre, stack) {
20 if (!nombre || !stack) {
21 throw new Error('Debes ingresar nombre y stack');
22 }
23 const campers = await leerCampers();
24 const nuevoCamper = {
25 id: campers.length > 0 ? campers[campers.length - 1].id + 1 : 1,
26 nombre: nombre.trim(), stack: stack.trim(),
27 creadoEn: new Date().toLocaleDateString()
28 };
29 campers.push(nuevoCamper);
30 await guardarCampers(campers);
31 return nuevoCamper;
32 }
33 export async function listarCampers() {
34 return await leerCampers();
35 }
36 export async function buscarCamperPorNombre(termino) {
37 const campers = await leerCampers();
38 return campers.filter(c => c.nombre.toLowerCase().includes(termino.toLowerCase()));
39 }

¿Cómo funciona export en EcmaScript?

En EcmaScript no usamos module.exports. Simplemente colocamos la palabra clave export antes de la función que queremos compartir. Esto se llama Exportación Nombrada (Named Export) y permite que index.js importe exactamente lo que necesita.

Ventaja de ESM: El editor (VS Code) ofrece autocompletado inteligente instantáneo de las funciones exportadas.
6 Paso 6: Enrutador de Consola (ESM)

src/index.js con Top-Level await

En EcmaScript Modules podemos usar await directamente en la raíz del script sin funciones envoltorias.

src/index.js (Líneas 1 a 24)
1 import { agregarCamper, listarCampers, buscarCamperPorNombre } from './campers.js';
2 const [, , comando, arg1, arg2] = process.argv;
3 try {
4 switch (comando) {
5 case 'agregar': {
6 const c = await agregarCamper(arg1, arg2);
7 console.log('✅ Camper registrado:', c);
8 break;
9 }
10 case 'listar': {
11 const lista = await listarCampers();
12 if (lista.length === 0) {
13 console.log('ℹ️ No hay campers aún.');
14 } else {
15 console.table(lista);
16 }
17 break;
18 }
19 default:
20 console.log('Uso: node src/index.js [listar | agregar | buscar]');
21 }
22 } catch (err) {
23 console.error('❌ Error:', err.message);
24 }
Línea 1 • Regla de Extensión .js Haz clic en cualquier línea 👈
Línea de código completa:
import { agregarCamper, listarCampers, buscarCamperPorNombre } from './campers.js';

¡Regla de Oro en EcmaScript!

En EcmaScript Modules en Node.js, la extensión .js es estrictamente obligatoria en rutas relativas. Si escribes from './campers' sin el .js, Node fallará inmediatamente con el error ERR_MODULE_NOT_FOUND.

Top-Level await en acción: Fíjate en la línea 6: escribimos await agregarCamper(arg1, arg2) directamente sin tener que envolverlo en una función asíncrona.

8 Paso 8 (Plus): Preguntas en Vivo

Preguntas Interactivas con ESM: node:readline

¿Cómo hacer preguntas interactivas en la terminal con EcmaScript sin librerías externas?

Usamos import para conectar la consola de Node.js de forma 100% nativa:

Componentes de node:readline en ESM:

  • import readline from 'node:readline/promises';
  • import { stdin as input, stdout as output } from 'node:process';
  • await rl.question('¿Pregunta?'): Espera la respuesta del usuario en la consola.
  • rl.close(): Libera la terminal para que Node termine su ejecución.
src/interactivo.js (ESM) 
import readline from 'node:readline/promises';
import { stdin as input, stdout as output } from 'node:process';
import { agregarCamper } from './campers.js';

const rl = readline.createInterface({ input, output });

try {
  console.log('=== REGISTRO INTERACTIVO DE CAMPERS (ESM) ===');
  const nombre = await rl.question('¿Nombre del camper? ');
  const stack = await rl.question('¿Stack tecnológico? ');

  const guardado = await agregarCamper(nombre, stack);
  console.log('🎉 Registrado en JSON:', guardado);
} finally {
  rl.close(); // ¡Obligatorio para que Node no quede congelado!
}
🐞 Guía de Depuración ESM

Los 4 Errores Clásicos en Node con EcmaScript

Basado en el repositorio de Debugging JS TS Node de Campuslands: errores específicos de ESM y cómo resolverlos.

1. ERR_MODULE_NOT_FOUND (Olvidar .js)

Causa: Escribir import { agregar } from './campers' sin extensión.
Solución: En ESM nativo de Node.js la extensión es obligatoria: from './campers.js'.

2. ReferenceError: __dirname is not defined

Causa: Usar la variable __dirname de CommonJS en un archivo ESM.
Solución: Reemplázala con fileURLToPath(import.meta.url) y path.dirname().

3. Cannot use import statement outside a module

Causa: Usar import pero olvidar poner "type": "module" en package.json.
Solución: Abre package.json y añade la línea "type": "module".

4. SyntaxError: Unexpected token in JSON

Causa: El archivo campers.json se creó vacío (0 bytes) manualmente.
Solución: Debe contener al menos [] para ser un array JSON válido, o dejar que el código lo cree con fs.writeFile.
